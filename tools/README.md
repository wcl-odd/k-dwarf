# Development-side paper-project maintenance

`make artifact` copies the current K sources, converts the reviewed frozen archive into self-contained source files, copies seven runtime modules and four root templates, and publishes four recorded-result files. `make artifact-check` checks correspondence; `make artifact-test` runs packaging and mock-runner tests. No symlink, compiled definition, cache, upstream tree or developer test is published.

The standalone corpus contains only `lldb.json`, `gdb.json` and a guide. Each expression case stores bytecode, a fixed interface and requirements. The `group` field distinguishes core and auxiliary cases for reporting, and `--source` reads only the requested source file(s). Source anchors and original quotations are documentation only. `tools/compact_cases.py` resolves archived observations during development-side export; standalone execution opens no upstream source or snapshot files. Full reviewed development inputs remain in `test-corpus/`.

The maintained runtime sources are `tools/artifact-runtime/{cases,requirements,dependencies,k,runner,processes,experiment}.py`. They load cases, check requirements, schedule attribute calls, invoke K, serialize the interface/observe K outcomes, manage child processes, and write reports. The interface validator and KAST serializer are separate; no alternate textual configuration is constructed. Observations read only frozen inputs, without live-memory collection hooks. The process helper records commands and outputs and handles timeout/interruption cleanup. Only K decodes or executes DWARF operations. Source selection and semantic mapping involved human/AI review; replay itself needs no AI.

`python3 tools/record_expression_results.py --run artifact/build/<completed-run> --output <new-directory> --jobs 16 --timeout 120 --depth 10000` packages actual per-case checks and all K outcomes, with recomputed coverage and English annotations. The current four-file maintenance copy is `docs/reference/artifact-results/`; the copier publishes it as `results/`. The older `compact_results.py` exporter reads development evidence only to inherit reviewed analyses/remarks. Neither exporter is shipped or used by the experiment runner. The current exporter reads per-case records and checks captured timeout/depth receipts; it never parses a Markdown report or reads a saved summary. Concurrency must be supplied explicitly because individual invocation receipts do not record it. Use --interrupted or --diagnostic to retain a known run-level interruption or diagnostic; incomplete case sets are refused. Publication requires the complete four-file maintenance package and refuses missing or damaged packages without falling back to historical formats.

Generation holds `/tmp/locks/kframework.lock`, stages under its own `/tmp/scratch/` directory, and rechecks source/destination hashes before writes. Existing managed files must match the prior local sync record. Independent edits, unknown files, symlinks and overlapping paths stop publication. Only unchanged, previously managed files and recognized regenerated bytecode may be retired; local build outputs survive. Sync identities and cleanup receipts stay under development `build/`, never in the standalone corpus.

The artifact Makefile only compiles. `validate.py` runs the existing LLVM definition with at most 16 concurrent cases, checks original requirements and writes fresh consistent/inconsistent counts. It never reads saved results. Development `verify.py` retains its separate input format and exit policy. The artifact has no publication manifest or corpus SHA authentication. K copies must remain byte-identical; synchronize them before development builds after a rule edit.

The minimal project was freshly evaluated on all 326 tasks (324 core plus two auxiliary) using 584 K invocations, including dependencies and stability probes. Terminology edits were checked against every saved outcome in a relocated copy; the development workspace and upstream sources were blocked from that check. Developer regressions, proofs, examples and cross-version probes are maintained outside the paper project.
